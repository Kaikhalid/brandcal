# brandcal 0.2.0

brandcal 0.2.0 introduces self-hosted **Cloudflare Workers + D1** deployment, **CLI remote mode**
for AI assistants, and complete setup documentation so anyone can deploy and connect their own
calendar from scratch.

## Highlights

- **Cloudflare Workers + D1 backend (`cloud/`):** serve the built Next.js web UI from Workers
  static assets and run the full console API on D1 with optimistic locking, Cloudflare Access JWT
  verification, per-page Content Security Policy hashes and daily JSON snapshots to KV
  (`BACKUPS`, 35-day retention) alongside D1 Time Travel (#53).
- **CLI remote mode:** point `BRANDCAL_REMOTE` at your Worker with a Cloudflare Access service
  token (`BRANDCAL_ACCESS_CLIENT_ID` and `BRANDCAL_ACCESS_CLIENT_SECRET`). Every command runs
  through the full Python core on a pulled snapshot and pushes verified row changes back through
  `/api/sync/apply`. Use `brandcal pull --out FILE` to save a read-only local SQLite copy (#53).
- **Conformance testing:** `tests/test_cloud_conformance.py` replays API and CLI scenarios
  against both `brandcal serve` (SQLite) and the Worker (local D1) to verify identical behaviour
  and unbroken audit chains (#53).
- **Public documentation and templates:**
  - Rewritten `README.md` with web UI screenshots (Example Co demo data) and a clear Status
    section.
  - From-zero Cloudflare deployment guide in `docs/CLOUDFLARE_SETUP.md`.
  - AI assistant integration guide in `docs/BOT_INTEGRATION.md` with a ready-to-paste
    instructions block, worked examples and a root `.env.example`.
  - Example `serve` configuration in `examples/config.serve.example.json` and `BACKUPS` KV
    placeholder in `cloud/wrangler.jsonc`.
  - Updated `SECURITY.md` supporting the `0.2.x` series.

## Bug fixes

- `brandcal next` and report sorting no longer crash on imported or idea posts that have no
  scheduled window (`window IS NULL`); unscheduled posts sort last (#54).

## Notes and deprecations

- **Relay and tunnel hosting are now historical:** `docs/DEPLOY_RELAY.md`,
  `docs/RELAY_CONNECTOR.md`, `docs/DEPLOY_UI.md` and `relay/` are kept for reference only. New
  deployments should use `docs/CLOUDFLARE_SETUP.md`.
- **`posts.extras` is frozen:** `posts.extras` is a one-time snapshot captured during `brandcal
  migrate` from v1 calendars. Integrations must always read the authoritative v2 columns
  (`posts.window`, `posts.status`, `parts.text`, `posts.platform_url`, `posts.published_at`).
- **Known limits:** brandcal is still an alpha release (v0.2.x). Media storage in Cloudflare mode
  (R2) is not yet implemented (the cloud media endpoint returns 404). `serve.console_approvals`
  remains `false` by default until explicitly enabled by the calendar owner.
